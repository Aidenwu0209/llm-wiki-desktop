# Product Parity Matrix: nashsu/llm_wiki and Obsidian-like Workspace

This document tracks R1 shell parity before picking the next small UI PR. It is a planning artifact only: it should expose gaps and deliberate product boundaries without changing ingest runtime, DeepSeek full-flow scripts, or open-llm-wiki strategy.

## Reference Snapshot

- Current repo: `Aidenwu0209/llm-wiki-desktop`, refreshed on 2026-05-28 from `main` at `642478d` (`shell(reading): make vault page preview the primary workspace`) plus the current reading-history / relation-pane follow-up slice.
- Reference app: [`nashsu/llm_wiki`](https://github.com/nashsu/llm_wiki), inspected from its public README and repository surface on 2026-05-28. The reference emphasizes recursive wiki navigation, markdown reading/editing, graph/KG exploration, semantic search, ingest automation, review, Deep Research, and local API/agent use.
- Obsidian baseline: standard desktop vault shell behavior: file explorer, markdown reading/editing, backlinks, graph, search, command palette, settings, tabs/panes, plugin ecosystem, and external app handoff.

Status labels:

- `same`: current shell has the same product surface and a comparable user path.
- `better`: current shell gives stronger behavior for the LLM Wiki Desktop product goal.
- `worse`: current shell has a missing or weaker capability.
- `intentionally different`: current shell diverges by product boundary, usually to preserve local-first, runtime-owned, evidence-first, or proposal-first behavior.

## Prioritized R1 Follow-up Slices

1. `shell(reading-main-pane)`: move the current read-only reader from the right rail into a stronger center/split-pane workspace.
2. `shell(backlinks-plus)`: add unlinked mentions and richer page-local relation filtering from local indexes.
3. `shell(graph-filter)`: filters for source, claim, concept, review, proposal, and warning nodes.
4. `shell(nav-polish)`: clearer source -> concept -> review -> proposal navigation beyond the current history/tabs and active-path reveal.
5. `shell(command-palette)`: broader read-only command registry and keyboard coverage.
6. `settings(section-parity)`: make reserved/gated settings honest without enabling hidden cloud/API flows.

## Non-goals For R1 Shell Parity

- Do not change PaddleOCR ingest runtime or parser invocation.
- Do not change DeepSeek full-flow scripts.
- Do not change open-llm-wiki runtime ownership or dependency strategy.
- Do not move OCR/ERNIE onboarding back to the public home/welcome page.
- Do not add direct source/concept editing or writeback apply shortcuts.
- Do not store real API keys in settings, vault state, docs, tests, examples, screenshots, or fixtures.
